# Project 7 - RainMaker Insights

## Mục đích của project 7

Project 7 là phiên bản mở rộng của chuỗi bài ESP32-C3 smart light, tập trung vào 2 ý chính: vẫn giữ đầy đủ luồng RainMaker như project 5, đồng thời bổ sung ESP-Insights để thu thập và chẩn đoán trạng thái thiết bị từ xa. Nói ngắn gọn, đây là mẫu `RainMaker + Insights` cho một thiết bị đèn Wi-Fi có OTA, provisioning, điều khiển từ cloud và diagnostic data.

Theo README của project 7, các chức năng vẫn gồm bật tắt đèn, cấu hình mạng bằng app RainMaker, OTA, và thêm support cho ESP-Insights diagnostic. README gốc của repo cũng mô tả toàn bộ bộ dự án là chuỗi các bước tăng dần, từ driver đèn, Wi-Fi, network config, RainMaker, tối ưu hoá, rồi mới đến Insights.

## Project 7 liên hệ gì với project 2 - 6

1. Project 2 cung cấp lớp driver đèn và PWM, tức phần phần cứng để điều khiển light.
2. Project 3 cung cấp kết nối Wi-Fi.
3. Project 4 cung cấp network provisioning/config để thiết bị tự vào mạng.
4. Project 5 thêm RainMaker cloud control, OTA, scheduling và cấu trúc app/device model.
5. Project 6 thêm tối ưu hoá khởi động, flash size và power management.
6. Project 7 kế thừa toàn bộ nền tảng đó và thêm ESP-Insights để giám sát, chẩn đoán và thu thập dữ liệu runtime.

Vì vậy project 7 không phải một app mới tách rời, mà là bản nâng cấp trên cùng nền code của 5 và 6, dùng lại các component chung trong `device_firmware/components/` như `app_wifi`, `app_storage`, `button`, `light_driver`.

## Những gì không đổi đáng chú ý

1. Không thấy thay đổi nội dung trong `main/app_main.c` và `main/app_driver.c`. Luồng app vẫn giữ nguyên: khởi tạo storage, driver, Wi-Fi, RainMaker, OTA, schedule và insights.
2. Không thấy thay đổi nội dung trong `main/include/app_priv.h`; file này chỉ tiếp tục đóng vai trò khai báo API chung cho driver, đèn và PM.
3. Không thấy thay đổi nội dung trong `main/CMakeLists.txt`; file này chỉ register source của component main và nhúng `server.crt`.
4. Các component local dùng chung như `app_wifi`, `app_storage`, `button`, `light_driver` vẫn là nền tảng cho project 7, kế thừa trực tiếp từ các project trước.

## Tại sao bản sửa này build được

1. Component Manager của ESP-IDF được dùng để kéo các dependency RainMaker/Insights thay vì phụ thuộc thủ công vào source tree ngoài. Điều này đúng với mô hình build system của ESP-IDF: `idf_component.yml` khai báo dependency, `managed_components/` chứa component đã tải, và `dependencies.lock` pin version.
2. `app_pm.c` bù đúng phần thiếu của cây gốc để resolve các symbol PM mà `app_driver.c` và `app_priv.h` đã trỏ tới.
3. `partitions.csv` được mở rộng để app image có đủ chỗ sau khi thêm các component của RainMaker/Insights, tránh lỗi binary không fit partition.
4. `sdkconfig` thể hiện cấu hình build thật đã bật Insights và các tính năng RainMaker cần thiết.

## Kết luận ngắn

Phần sửa của project 7 chủ yếu không nằm ở business logic của `app_main` hay `app_driver`, mà nằm ở việc hoàn chỉnh lại build graph: thêm `app_pm.c`, chuyển sang dependency-managed build với `idf_component.yml` và `managed_components`, tăng kích thước OTA partitions, và chốt `sdkconfig` cho một cấu hình có ESP-Insights.

Lưu ý nhỏ: top-level `CMakeLists.txt` vẫn còn check `RAIMAKER_PATH` dù các đường dẫn RainMaker đã bị comment. Nếu muốn bỏ phụ thuộc vào việc clone repo RainMaker bên ngoài hoàn toàn, phần guard này là ứng viên cần dọn tiếp.
